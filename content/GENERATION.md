# GENERATION.md — パッセージ生成パイプライン(WP2)

`content/passages/*.json` を量産するための手順書。難度の基準は `content/calibration.md`(以下「基準」)、スキーマは SPEC v1 §4.1、誤読タイプは §4.2、機械検証は `content/validate.mjs`。

パイプラインは **生成 → 自己検品 → 機械検証 → 人手検品 → コミット** の5段。開発セッション内で完結し、ランタイムでは一切生成しない(教材は静的JSON)。

---

## 0. 前提と原則

- **本文は必ず新規に書き下ろす**。既存作品の複製・翻案は禁止。寄せてよいのはジャンル・文体の傾向だけ。
- **文法的正しさを難度より優先する**。自信のない構文は使わず、平明な構文に書き換える。長さは入れ子と挿入で作る。
- 絵文字を使わない(本文・note_ja・title_ja・コミットメッセージすべて)。
- 実在の人物・団体への言及を書かない。企業案件の情報を書かない(公開リポジトリ)。
- 1バッチは **3〜6本**。それ以上は検品が形骸化する。

---

## 1. バッチの設計(生成前に決める)

生成を始める前に、そのバッチの割り当てを表にして確定する。

| 項目 | 決め方 |
| --- | --- |
| フェーズ | 配信予定時期に対応(基準 §3)。P1期は Lmax 昇順で並ぶよう設計する |
| ジャンル配分 | essay : practical : narrative = 2 : 1 : 1 を目安(基準 §1) |
| トピック | 一般教養から。音楽は全体の1〜2割。**既存本のトピックと重複させない**(`content/passages/` の title_ja を確認) |
| id | 既存の最大id + 1 から連番(p0007, p0008, …) |
| ファイル名 | `YYYY-MM-DD_<id>.json`(生成日) |

## 2. 生成プロンプト・テンプレート

`{{ }}` を埋めて使う。Claude/LLMに渡す。**1回の呼び出しで1本**(複数本を同時に書かせると難度の作り込みが甘くなる)。

````text
あなたはイタリア語教材の執筆者です。日本人学習者(CEFR B1〜B2、大学院入試の全文和訳対策)向けに、
オリジナルのイタリア語散文パッセージを1本書き、指定のJSONで出力してください。

## 絶対条件
- 本文は完全にあなたのオリジナルとする。既存の書物・記事の複製・翻案・要約をしない。
- イタリア語の文法的正しさを最優先する。自信のない構文は使わず、平明な構文に書き換える。
- 実在の人物・団体・商品への言及を書かない(架空の人名は可)。
- 絵文字を使わない。
- 現代イタリア語の散文とする。古語・韻文・オペラのリブレット的語法を使わない。

## 難度パラメータ
- フェーズ: {{P1|P2}}
- ジャンル: {{essay|practical|narrative}}
- トピック: {{例: 都市の街路樹の管理}}
- 総語数: {{100〜130 | 180〜250}} 語(空白区切りで数える)
- 文数: {{4〜6 | 6〜8}}
- 最長文: {{25〜35 | 40〜60}} 語。ただし「長いだけ」の文にせず、
  従属節の多重化({{2〜3 | 3〜5}}個)と挿入によって長くする。
- 1文あたりの関係節+従属節の平均: {{1.0〜1.8 | 1.8〜2.8}}
- 主語と述語の間、または動詞と目的語の間に割り込む挿入の最大語数: {{2〜5 | 6〜12}}
- 段落: {{1〜2 | 2〜3}}(本文中では \n\n で区切る)

## 文体
- essay: 中立的・論述的。主張動詞 + che + 接続法、受動態(essereとvenireを書き分ける)、
  相関構文(non… ma/bensì、più… che)を用いる。
- practical: 平明な助言の口調。非人称の si、一般人称の chi、conviene / basta / è utile 型、
  se + 接続法半過去 → 条件法現在 の仮定文を用いる。
- narrative: 三人称の語り。遠過去(passato remoto)を必須とし半過去と対比させる。
  過去未来(sarebbe venuto 型)と come se + 接続法を各1か所以上。

## 必ず含める文法要素
- 関係節(che / cui / 前置詞+cui): {{2 | 4}} か所以上。P2では1か所を主語と述語を隔てる位置に置く。
- 接続法: {{1 | 2}} か所以上
- コンマまたはダッシュで括られる挿入句: {{1 | 3}} か所以上
- 代名詞の照応(lo/la/le/gli/ne/ci、所有 proprio): {{3 | 5}} か所以上
- 過去分詞句またはジェルンディオ句: {{1 | 2}} か所以上

## 仕込む「罠」
各文に、以下の型の誤読ポイントを1〜3個、自然な形で仕込む。文法的な誤りや曖昧な悪文にはしないこと。
SYN(主語と動詞を隔てる/動詞の後に主語)、MOD(一致で修飾先を決めさせる)、
REF(1文に複数の代名詞)、MOOD(接続法・条件法・過去未来・finché non の虚辞のnon)、
LEX(多義語・成句)、OMIT(訳し落としやすい列挙・挿入)、ADD(補いたくなるが補うと誤りになる簡潔さ)

## 出力
次のJSONのみを出力する(前後に説明文を書かない)。

{
  "id": "{{p0007}}",
  "phase": "{{P1|P2}}",
  "genre": "{{essay|practical|narrative}}",
  "wordCount": 本文を空白区切りで数えた実数,
  "title_ja": "日本語の短い表示用タイトル",
  "text": "イタリア語本文。段落は \n\n で区切る",
  "sentences": [
    {
      "idx": 0,
      "text": "原文1文(textから一字一句そのまま切り出す)",
      "words": この文を空白区切りで数えた実数,
      "skeleton": {
        "mainVerb": "主節の動詞(複数なら併記)",
        "subject": "主節の主語(省略されているなら「(…)省略」と書く)",
        "core_ja": "挿入と修飾をすべて外した骨格だけの直訳"
      },
      "clauses": [
        {"span": [開始語index, 終了語index], "type": "rel|sub|ins|ger",
         "note_ja": "その節・句が何を修飾し、どの語が手がかりになるかの日本語の説明"}
      ],
      "model_ja": "この文の模範訳",
      "traps": ["SYN", "MOOD"]
    }
  ],
  "model_ja_full": "全体の模範訳(段落は \n\n)",
  "vocab": [{"it": "見出し語", "ja": "語義", "hint": "辞書を引くべき|推測可"}]
}

### spanの数え方(厳守)
- 語 = その文の text を trim して /\s+/ で分割したトークン。句読点は直前の語に付いたまま数える。
- index は 0 始まり、span は [開始, 終了] の**閉区間**。
- 節の範囲は、その節を構成する語だけを含める(直前の先行詞や、末尾の等位接続詞 e を含めない)。
- 入れ子は入れ子のまま両方書いてよい(外側の span の中に内側の span が入る)。
- **書く前に必ず語を1つずつ数える**。推定で書かない。

### vocab
- 5〜8語。本文に現れる語のみ。
- hint は「辞書を引くべき」(多義語・成句・誤推測しやすい語)か「推測可」のいずれか。

## 出力前の自己検品(この手順を実行してから出力する)
1. 本文を1文ずつ数え、総語数と最長文の語数が上の指定内に入っているか確認する。外れていたら書き直す。
2. すべての動詞の活用・時制の照応、すべての形容詞・過去分詞の性数一致を1つずつ確認する。
3. すべての代名詞について、指す相手が文法的に一意に決まることを確認する。曖昧なだけの文なら書き直す。
4. 必須文法要素(上記)を1つずつ数え、不足があれば本文を書き直す(語注や説明で埋めない)。
5. すべての clauses について、span で切り出した語列が note_ja の説明と一致することを確認する。
6. sentences[].text を順に連結したものが text と一致することを確認する。
7. 既存作品の言い回しをなぞっていないことを確認する。
````

## 3. 生成後の手順

### 3.1 保存

`content/passages/YYYY-MM-DD_<id>.json` として保存する。**LLMの出力をそのまま信じない**。特に `wordCount` / `words` / `span` は自己申告なので、次の機械検証で必ず潰す。

### 3.2 機械検証

```bash
cd /Users/user1/opera-italian-reader
node content/validate.mjs                       # 全件
node content/validate.mjs content/passages/2026-08-07_p0007.json   # 単体
echo $?                                          # 0 でなければ不合格
```

`validate.mjs` が見るもの:

- 必須フィールドの有無と非空
- `phase` / `genre` / `clauses[].type` / `traps[]` / `vocab[].hint` のenum
- `sentences[].idx` の連番、`words` の実数一致
- `clauses[].span` が [整数, 整数]、開始 ≦ 終了、終了 < その文の語数
- `sentences[].text` が `text` の部分文字列であること、語数合計の一致
- `wordCount` の実数一致(±10%)
- ファイル名と `id` の一致、絵文字の不在
- フェーズ別の W / Lmax レンジ逸脱(**WARN**。FAILにはしない)

**FAILが出たら直す。WARNは意図的かどうかを人が判断する。** wordCount のずれは数え直して修正、span のはみ出しは数え直して修正するのであって、レンジの方を緩めない。

### 3.3 span の目視確認

機械検証は span が範囲内かしか見ない。**切り出した内容が説明と合っているかは人が見る**。

```bash
node -e 'import("node:fs").then(fs=>{for(const f of fs.readdirSync("content/passages").sort()){
const d=JSON.parse(fs.readFileSync("content/passages/"+f,"utf8"));console.log("=====",d.id);
d.sentences.forEach(s=>{const w=s.text.trim().split(/\s+/);
s.clauses.forEach(c=>console.log(` s${s.idx} [${c.span}] ${c.type}: ${w.slice(c.span[0],c.span[1]+1).join(" ")}`));});}});'
```

よくある不良: 節の末尾に等位接続詞 `e` を巻き込む / 先行詞を節に含める / 主節全体を `rel` として囲う。いずれも1文ドリルの正誤判定を狂わせるので必ず直す。

### 3.4 人手検品

`calibration.md` §6 のチェックリスト A〜E を上から実施する。1つでも×なら破棄または修正。**全項目を通ったものだけをコミットする。**

### 3.5 コミット

```bash
cd /Users/user1/opera-italian-reader
node content/validate.mjs && git add content/passages && \
git commit -m "content: パッセージ p0007-p0010 を追加(P2 essay×2/practical/narrative)

checked: 4/4 (calibration.md §6 A-E)
validate.mjs: 10/10 PASS, WARN 0"
```

- `validate.mjs` を通してからでなければコミットしない(`&&` で連結する)。
- 検品件数 `checked: n/n` をコミットメッセージに残す。
- 公開リポジトリのため、コミット前に企業案件情報の混入がないことを grep で確認する(既存方針)。

## 4. 再生成の判断

| 症状 | 対処 |
| --- | --- |
| 語数・最長文がレンジ外 | プロンプトのパラメータを変えずに再生成。2回続けて外れるならトピックが短すぎる/長すぎるので変える |
| 文法誤り・不自然表現が2か所以上 | そのパッセージは**破棄**して再生成(部分修正で辻褄を合わせない) |
| 長さが入れ子でなく列挙だけで稼がれている | 「従属節の多重化」を指示に強調して再生成 |
| span の不良が3か所以上 | 本文は維持し、sentences 以下だけを数え直して作り直す |
| 難度が明らかに易しい | Lmax と挿入の最大語数を上げるのではなく、**主語と述語を隔てる関係節**を増やす指示にする |

## 5. P3(模試)パッセージの作り方

P3 は「独立した2題」であり1本の長文ではない。**別々に生成した essay系1本(175〜225語)と narrative系1本(175〜225語)を組にする**。JSONは1題1ファイルのままとし、模試モード側で2ファイルを組にして出題する(組の定義はWP4以降のアプリ側で持つ)。1ファイルに2題を詰め込まない。
